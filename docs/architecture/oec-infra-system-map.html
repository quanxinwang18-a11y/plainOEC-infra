plainOEC-infra
从需求到验证的可组合能力地图

01 / LAYERS

一张图看懂：谁解释，谁执行，谁保存事实

Marketplace 只负责发现和分发。Product、Engineering、Dev Beta、Common 面向模型；E3 与 Pipeline 是独立平台 Plugin。平台 Plugin 不反向依赖某一种产品或研发流程。

实线 = 分发或运行依赖
虚线 = 用户按场景组合 / 宿主复用
宿主分发 / 平台运行 按需组合 / 复用，不是强制阶段 刻意没有：统一 oec-delivery、全局 Router、默认 Dev Orchestrator。
01

模型处理语义

PRD、Spec、技术权衡和 Human choices 保留在模型与用户判断侧。

02

代码处理不变量

路径 containment、schema、身份、fingerprint、幂等和恢复不交给 Prompt 临场猜测。

03

风险决定流程长度

小修复走 Main Session 短路径；跨模块、数据、兼容性或高风险任务才展开上下文与门禁。

04

证据等级显式化

源码、自动测试、bundle、Connected、真实非生产验收和生产可用不能互相替代。

边界口诀：用户提供目标而不是内部流程；Skill 讲“怎么判断和产出”；Agent 提供“为什么需要隔离”；runtime 验证“本地是否符合契约”；MCP 执行“外部系统能否安全改变”；Human 决定“是否值得承担这次副作用”。规划确认后，主会话沿着原目标继续，不把内部 taskRef 再交回用户手工路由。

03 / CAPABILITY CATALOG

能力不是流程阶段：按用户目标发现并组合

下方列出当前可用的 Skills、Agents、MCP Tools 和 oec-spec runtime。Skill 被调用不等于获得 commit 或远端写入授权；Agent 也不是普通任务的必经阶段。

名称保持仓库原始标识；描述聚焦“做什么 / 不做什么”

Product Skills

写作、评审与明确发布意图均可按目标发现；远端写入保持确认门

prd-writemodel-discoverable

创建、修订和定稿 versioned PRD，并拆分 child PRD、Story、acceptance criteria 与 HANDOFF.yaml，维护产品 SSOT。

不做：只读评审、技术设计、E3 发布或研发任务操作。
prd-reviewread-only

对现有 PRD 做红队评审，找歧义、冲突、不可测试验收条件、越权技术设计和未决业务决定。

不做：修改 PRD、Review 代码、发布 E3 或管理 E3 研发任务。
prd-publishdiscoverable / confirmed

只对已 finalized、child PRD 与 HANDOFF 完整的版本启动发布语义：准备、展示计划、Human confirmation、执行、状态验证。自然语言发现不会跳过确认。

不做：写 PRD、发布不完整产物或自动因为 PRD 完成而写 E3。
prd-manager Agent：需要持续产品身份时显式选择。它预加载 prd-write 与 prd-review，刻意不预加载 prd-publish；产品事实、优先级、范围和验收由它负责，API / 数据库 / 部署设计留给 Engineering。

Engineering Skills

guide 是 SessionStart bootstrap，不是业务入口

guidebootstrap / hook

在 startup | clear | compact 注入静态行为约束：从用户目标发现相关能力，并用用户语言解释最有用的下一步；用户不必知道 Skill、taskRef 或内部文档名称。

不做：列能力清单、扫描项目、选择 taskRef、创建状态或充当 Router。
code-planplanning gate

为来自 PRD、Story、HANDOFF、issue 或其他非平凡变更的请求建立已确认的 scope、acceptance、technical direction 和安全代码边界；按需生成最小 spec.md + design.md，不要求用户掌握内部文档名。

不做：直接改业务代码、执行外部平台或规定固定编码顺序；确认后把原目标交回实现。
code-implementexisting ready task

接收已有 ready task，或在确认规划后继续原始开发目标；先 resolve/check，再读取 Spec、Design、Change Boundary，由 Main Session 实现并跑验证，不要求用户重复内部身份。

前置：task check --stage ready 通过；不创建任务、不派 Agent、不调用 E3/Pipeline、不 commit。
code-reviewread-only

按风险评审 working-tree diff、commit、branch 或 PR；每个 finding 给出位置、触发输入、后果和最小修正方向，并可报告 stale Spec 候选。

不做：实现请求、创建 review artifact、stage 或 commit。
knowledge-manageexplicit intent

在明确要求时创建或更新有代码证据支持的 current-state Specs、ADR 和必要 change package；remind 模式只读。

不做：把普通 implementation plan 写成团队事实，或没有证据时创建空文档。
test-firstexplicit TDD

仅在用户明确要求 TDD / test-first / red-green-refactor 时采用窄纵向 slice，先确认测试因缺失行为失败，再实现最小代码。

不做：替换仓库测试策略，也不因“改动应该有测试”自动触发。
debugrisk-triggered

处理难复现、flaky、性能回退、反复修复失败或根因不清的问题；先建立可重复信号，再用最便宜的观察区分假设。

停止条件：多次修复仍失败时回看架构或假设，不继续堆叠补丁。
decision-reviewexplicit challenge

压力测试一个技术决定，拆分事实、假设、依赖和 Human choices，输出支持、拒绝、延期或阻塞的决定 frontier。

不做：普通 planning、自动建任务、自动写代码或替代已接受 ADR。
prototypethrowaway

创建最小临时 artifact，回答一个交互、行为或状态模型问题，让 Human 观察并选择方案。

不做：把原型自动升级为生产实现，或用原型替代可直接完成的测试 / benchmark。
docs-migrateexplicit migration

从旧 ai-docs 中提取仍被当前代码证明的工程事实和有效决定，迁入当前 Specs、ADR 或 change package。

原则：保留旧文件；不删除 managed config、E3 record 或历史状态。
code-finishexplicit close

检查最终 diff、真实验证证据、相关 Specs / ADR 和残余风险；仅在用户确认精确路径后可选 commit。

不做：部署、创建 release、更新 E3/SAE/UTP，或把调用 Skill 当成 commit 授权。

oec-spec deterministic runtime

自足 bundle；不判断设计质量

为什么需要 runtime？

任务身份、路径边界、Frontmatter、章节、来源链接和 Acceptance ID 需要可重复验证。runtime 负责结构与安全；模型仍负责产品语义和技术判断。

lexical containmentrealpath containmentno silent ambiguity
oec-spec select按受影响路径和 applies_to 选择相关 Specs / ADR；拒绝 workspace 外路径。
oec-spec check校验 Team Spec / ADR / change contract 的结构；不评审内容质量。
oec-spec task resolve统一解析 versioned / unversioned taskRef；不在多个候选中静默选择。
oec-spec task check校验 Spec/Design 的身份、路径、来源、章节、Acceptance 和交叉引用；profile 为 structure / ready / close。
oec-spec remind只读报告可能受影响的 Spec / ADR，不写文件、不创建状态、不阻断 Direct Coding。
oec-spec legacy-audit只读审计旧 ai-docs 和 managed configuration；不删除、不自动迁移。

Agents：只在隔离价值明确时使用

产品 1 + Engineering 4；均不是普通编码必经阶段

prd-manager

显式 PM 身份；负责产品行为、用户故事、验收、范围、优先级和 changelog。

preloads: prd-write · prd-review

implementer

读取已有任务 Spec/Design，在 Change Boundary 内隔离实现；验证不足时只能报告 partial/failed。

no commit · no push · no merge

checker

fresh-eyes 检查 staged / unstaged / untracked diff、契约和测试；可修复明确机械问题。

不把观点写成 Team Spec

researcher

对已有 taskRef 做有边界研究，只把结果写入该任务的 research/，不改代码或任务契约。

primary sources + caveats

evaluator

使用预配置 Playwright 对本地或内部非生产 Web 应用做运行态验收；不修改源码、文档或 Git。

Playwright 不可用 → blocked
选择原则：Agent 提供独立身份、干净上下文或 fresh-eyes，不负责创建 Spec/Design，不派生其他 Agent，不 commit / push / merge。Codex TOML 是由 Markdown 事实源生成的镜像，完整宿主验收仍需单独声明。

E3 MCP · 10 typed tools

同一认证、状态、Owner 和远端生命周期，因此暂不拆成两个平台 Plugin

共同门禁：prepare 只读且不创建远端对象；必要时 select 唯一候选；execute 只接受 workspace-bound 的短期 immutable plan，并要求宿主人类交互；status 独立 read-back。身份、漂移、未知响应和并发不确定时默认 blocked / partial / unknown。Product 依赖会让宿主看到完整 10 Tools，但 Product Skill 仍只允许对应的发布语义。

只运行已有的 dev / test pipeline；不提供通用 CRUD

05 / CONTRACTS & STATE

任务身份、双空间与三类事实

Engineering 的稳定性来自统一的 taskRef 和安全来源解析，而不是每个 Skill 各写一套路径拼接。项目资产、Plugin 私有状态、远端最终对象各有 Owner。

任何绝对路径只可作为当前进程返回值，不能写进持久化文档

Canonical taskRef

优先显式 --task-ref，其次明确目录、version + slug，再兼容 legacy change ID；不接受裸 slug、模糊 latest、绝对路径、.. 或多个候选静默选择。

versioned:v1.2.3/payment-retry
change:2026-09-02-cache-fix
featureName产品 / 外部语义，例如 paymentRetry
task-slug目录身份，例如 payment-retry
externalChangeIdE3 身份，例如 v1.2.3-paymentRetry
resultresolved / missing / ambiguous / invalid / unsafe

Product Root ↔ Dev Root

Engineering 从 Product Root 只读 PRD、Child PRD 与 HANDOFF；任务 Spec、Design、Team Specs 和 ADR 只写入 Dev Root。双空间模式引用来源，不复制产品文档。

  • read by Engineering

DEV_ROOT · Dev / team owner

  • 业务代码
  • ai-docs/versions/*/dev-task/
  • ai-docs/Spec/
  • write task artifacts here

06 / GET STARTED

使用方式：先按角色安装，再从安全场景开始

user scope 是默认推荐：不会因为安装 Plugin 就向业务仓库复制 .claude、.codex 或 ai-docs。不要一次性安装全部 Plugin。

前提：Claude Code ≥ 2.1.110 · Node.js ≥ 20 · 有权读取 Marketplace Git 仓库

① 添加 Marketplace（一次）

  • 每个用户只需添加一次 Marketplace。
  • 不需要 npm login、GitHub Packages 或手工复制 payload。
  • Product 安装时由宿主自动解析 oec-e3@~1.0.0。
claude plugin marketplace add \
  quanxinwang18-a11y/plainOEC-infra \
  --scope user

② 按角色选择 Plugin

产品

先安装 Product；需要汇报时再加 Common。

claude plugin install \ oec-product@plainOEC-infra \ --scope user

研发

先安装稳定 Dev；Beta / E3 / Pipeline 按任务加装。

claude plugin install \ oec-dev@plainOEC-infra \ --scope user

其他 / 内容

只需要 HTML 演示时独立安装 Common。

claude plugin install \ oec-common@plainOEC-infra \ --scope user

受控 / 实验能力只在明确任务和授权对象上追加：

claude plugin install oec-dev-beta@plainOEC-infra --scope user
claude plugin install oec-e3@plainOEC-infra --scope user
claude plugin install oec-pipeline@plainOEC-infra --scope user

③ 第一次使用：从低风险、只读或 prepare 开始

根据这份需求材料写一版 PRD，先不要发布到 E3。
只读评审当前工作区 diff，优先报告会改变行为、兼容性或数据完整性的问题。
为当前 Change 准备研发任务计划，展示将创建或复用的对象，不要执行。
发现当前仓库可用的 test 流水线并展示执行计划，不要运行。
把这份材料做成一套 HTML 幻灯片。
