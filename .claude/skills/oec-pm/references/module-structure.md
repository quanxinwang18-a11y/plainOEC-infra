# 增量 PRD 模块 11 章结构

每个 `## 模块:` 内部按此结构组织（split 按此切片）：

### 1. 模块概述
| 字段 | 值 |
|------|----|
| 产品定位 | ... |
| 目标用户 | ... |
| 核心价值 | ... |
| 优先级 | P0 / P1 / P2 / P3 |
| 预估工作量 | S / M / L / XL |
| 影响模块 | ... |

### 2. 用户故事
作为 X，我希望 Y，以便 Z。每条带优先级。

### 3. 使用场景
前置条件 / 操作步骤 / 期望结果 / 异常路径

### 4. 交互流程
4.1 页面结构 / 4.2 Mermaid flowchart / 4.3 ASCII Wireframe / 4.4 表单约束

### 5. 验收标准（GWT，按 US 分组）
每个 US 至少覆盖正常路径 + 1 异常 + 1 边界

### 6. 状态与生命周期
仅当有状态流转对象时填写 Mermaid stateDiagram

### 7. 跨模块关联
| 关联模块 | 关联方式 | 用户感知 |

### 8. 非功能性需求与边界场景
异常 / 安全 / 外部依赖 / 性能感知（用户视角）

### 9. 数据变更（产品视角）
| 用户行为 | 系统记录 | 用户感知 |

### 10. 补充发现
来自原 PRD 的要点 / 细化发现的遗漏 / 跨模块关联

### 11. 待人工确认项
| 序号 | 事项 | 默认假设 | 影响范围 | 决策方 |

## 门控

- `[hard]` 跨模块关联表必须填（无关联也写"无"）
- `[hard]` `[待确认 N]` 必须配默认假设 + 影响范围 + 决策方
- `[soft]` 每个模块建议 ≥ 3 条用户故事
- `[soft]` 涉及 UI 建议带 ASCII Wireframe + Mermaid flowchart
